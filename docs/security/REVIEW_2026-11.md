# Security review — 2026-11

Scope: FastAPI backend (`backend/`), Expo app (`mobile/`), repo history. Defensive
code review with local tests only; no live hosts were probed.

Regression tests: `backend/tests/test_security_idor.py` (every id route, cross-user → 404)
and `backend/tests/test_security_review.py`.

## Findings

| # | Severity | Area | Location | Finding | Status |
|---|----------|------|----------|---------|--------|
| H1 | High | eBay public photo URL | `routers/integrations.py` `ebay_listing_image`, `services/ebay_listing.decode_data_url` | Served the stored data-URL media type verbatim. Inventory photo fields are unvalidated, so a stored `data:image/svg+xml` (or `text/html`) photo was served as active content from the app's own origin — stored XSS able to read web-session tokens from localStorage. | Fixed: type sniffed from magic bytes (JPEG/PNG/GIF/WebP only), size cap, `CSP: default-src 'none'; sandbox` |
| M1 | Medium | Webhooks | `routers/webhooks.py` (Stripe), `routers/integrations.py` (Square) | Unsigned events accepted whenever `ENVIRONMENT != "production"` and no secret set — a staging host or a mistyped ENVIRONMENT accepted forged subscription/payment events. | Fixed: unsigned only in `development`/`testing`; otherwise 503 with no side effects |
| M2 | Medium | Spreadsheet import | `services/spreadsheet_import.py` | XLSX (zip) inflated without limits: a <1 MB file could expand to GBs (memory DoS). | Fixed: `assert_safe_xlsx_archive` caps total inflated size (300 MB), member count, compression ratio → 413 |
| M3 | Medium | AuthN | `dependencies/auth.py` | Access tokens without a `sid` were accepted and could not be revoked by logout/password reset. | Fixed: `sid` required and validated against a live `AuthSession` |
| L1 | Low | AuthZ | `GET /integrations/ebay/listings/{item_id}` | Returned 200 `listed=false` for another user's item (no data leaked, but existence oracle). | Fixed: 404 unless owned |

## Verified OK (no change)

- IDOR: all 41 id-route/method pairs return 404 to a second user; victim data unchanged after all mutating attempts. `/sellers/{user_id}` is intentionally public.
- JWT: algorithm pinned (`algorithms=[ALGORITHM]`, `alg=none` rejected), `exp` set, `typ=access` required so OAuth-state JWTs cannot authenticate. Production refuses a default/short `SECRET_KEY`.
- Password reset: SHA-256 hash stored, 30-min expiry, single use, all sessions revoked on reset.
- Limiter: only `ENVIRONMENT=testing` disables it.
- RevenueCat: `hmac.compare_digest`; 503 if unconfigured. eBay notifications/deletion: signature required (412), deduped via `claim_webhook_event`; deletion is idempotent.
- Tokens: provider tokens encrypted at rest (`security/token_encryption.py`); not returned by status endpoints.
- SSRF on import-by-URL: DNS + connected-peer checks, redirect re-validation, size caps. CSV formula injection guarded on export.
- SPA serving: lookups only in a prebuilt allowlist map (no traversal). Security headers (HSTS, nosniff, `X-Frame-Options: DENY`, referrer, permissions) on every response; 55 MB body cap. Docs/OpenAPI off in production. CORS: explicit origins only in production.
- SQL: ORM / bound `text()` parameters only.
- Secrets: history grep for live Stripe/AWS/GitHub/Resend/Discord-webhook/private-key patterns found nothing; only `.env.example` files tracked. `EXPO_PUBLIC_*` = API base URL and RevenueCat public iOS key (public by design).

## Owner actions (prod env)

- Ensure prod `ENVIRONMENT=production` (exactly) and `STRIPE_WEBHOOK_SECRET`, `SQUARE_WEBHOOK_SIGNATURE_KEY` (if Square is used), `REVENUECAT_WEBHOOK_AUTH`, `PROVIDER_TOKEN_KEY` are set. Square/Stripe webhooks now return 503 in any non-dev environment without them.
- After deploy, any client holding a pre-session (sid-less) access token gets 401 once and re-logs in via refresh (all current logins already carry `sid`).
